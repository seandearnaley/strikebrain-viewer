# Milestone 9: updates — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The app learns of a newer release on GitHub, downloads and verifies the file for its platform, and installs it on one click through whatever owns the installation; then release 0.1.2 with it.

**Architecture:** A new `update` module in the viewer crate. Pure parts (`update/feed.rs`: the release JSON, the version comparison, the choice of file; `update/install.rs`: how this installation is updated) are plain functions with unit tests. `update/download.rs` streams a file into the cache folder and checks its size and digest. An `Updater` entity (`update.rs`) holds the phases, schedules checks on GPUI's timer and runs the network and file work on the background executor. The root view owns the updater, saves its two settings, shows its one button in the bar and handles three actions. Per-platform installers (`update/macos.rs`, `update/windows.rs`, `update/linux.rs`) do the last step.

**Tech stack:** Rust 1.100.0, `gpui-kit =0.10.0`, `ureq` 3 (`platform-verifier`, `json`), `semver` 1, `sha2`, `directories` 6 (already a dependency), `serde`/`serde_json` (already).

**Spec:** `docs/superpowers/specs/2026-11-22-strikebrain-viewer-design.md`, "Milestone 9: updates" (line 566 on). Read it before each task. GPUI Kit's guide it follows: https://gpui-kit.com/docs/auto-update.md.

### Task 4: macOS — verify the app and replace the bundle

**Files:** create `crates/viewer/src/update/macos.rs` (`#[cfg(target_os = "macos")]`); `update.rs` routes `Owner::MacBundle`/`MacUnreplaceable` here.

**What it does** (the spec's "Downloading and verifying", macOS):
1. `signed_by(app: &Path) -> Option<(String /*team id*/, String /*identifier*/)>` from `codesign --display --verbose=2 <app>` (stderr lines `TeamIdentifier=` and `Identifier=`); the running app's must exist and its team id must not be `not set`, else the owner is `ReleasePage` (refine `Owner::detect` here).
2. `stage(dmg: &Path, installed: &Path, team: &str, id: &str) -> Result<PathBuf, Error>`: `hdiutil attach -readonly -nobrowse -noautoopen -mountpoint <tmp>` the DMG; find the one `.app` in it; `codesign --verify --deep --strict`; `spctl --assess --type execute`; `signed_by` equal to the running app's; `ditto` it to `<installed's parent>/.Strikebrain Viewer.update/<name>.app` (same volume); always `hdiutil detach`. Any failure removes the staged copy.
3. `can_replace(installed: &Path) -> bool`: the parent folder is writable and the app is not translocated (its path does not contain `/AppTranslocation/` and is not on the DMG's volume); if not, the offer's `How` is `Install` and installing opens the DMG with `open_with_system`.
4. `swap(installed: &Path, staged: &Path) -> Result<(), Error>`: rename installed → `<staged dir>/old.app`, staged → installed; on failure rename old back; then remove `old.app` and the staging folder. Then `cx.set_restart_path(installed)` and `cx.restart()`.

- [ ] **Step 1: Failing tests** (temporary folders, fake bundles made of folders and a file): `swap` puts the new bundle in place and removes the old and the staging folder; if moving the new bundle fails (make the target's parent read-only after moving the old one aside, or inject the rename through a small `fn` parameter), the old bundle is back where it was; `can_replace` is false under a read-only parent and for a path containing `/AppTranslocation/`; `signed_by` parses a recorded `codesign` output (factor the parsing into a pure function and test it).
- [ ] **Step 2: Fail; Step 3: implement** (commands through `std::process::Command`, run on the background executor; read `hdiutil`, `codesign`, `spctl` and `ditto` man pages for the flags). **Step 4: pass; `just check`; commit** `feat(viewer): on macOS, an update replaces the whole signed app and relaunches`.
